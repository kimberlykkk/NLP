# Code Review Workflow

在完成代码修改后按以下顺序自查：

1. **改动范围**：用 `git_diff`（或 `search_files` 对比）列出本次改动，确认只改了
   与 issue 相关的文件，没有顺手改别的。
2. **逻辑正确**：读一遍改动后的函数，对照 issue 的验收条件逐条核对
   （如 `add(2,3)==5`、`add(-2,3)==1`、`factorial(5)==120`）。
3. **边界情况**：负数、零、空输入、类型错误是否处理，是否会引入新异常。
4. **测试覆盖**：确认现有测试覆盖了改动点；改动不该破坏既有测试。
5. **输出结论**：用一句话说明「改了什么、为什么对」，再给出「是否可以收尾」的判断。
